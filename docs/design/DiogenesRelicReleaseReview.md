# 第欧根尼放下凭借载体审查

## D133范围与源码证据

本阶段只读本机游戏程序集，SHA256为0861BFA1DF347538D932F22D580E75420F08082792EB914E53B4882764ACDBE9；核实RelicCmd、Player、Hook、PlayerCombatState、Ectoplasm、Sozu、VelvetChoker、NChooseARelicSelection，并用忽略目录中的完整反编译只统计远古遗物覆盖。未调用移除、保存或游戏对象，未启动Godot、Steam或游戏。

- RelicCmd.Remove先写当前地图历史的RelicsRemoved，再从玩家列表移除并调用AfterRemoved。三件目标都没有自定义AfterRemoved，不存在其类内另行补偿。
- 异质、添水、天鹅绒项圈各提供1点最大能量；限制分别是金币获得为0、禁止取得药水、每回合第7张及以后牌不可打。
- Hook每次从当前局/战斗监听者迭代。遗物移出列表后，后续金币/药水/出牌检查不再经过它；PlayerCombatState.MaxEnergy也在读取时从玩家基础值重新应用当前监听者，下一次回合重置失去该1点能量。未实测当帧UI刷新，不把源码推断写成进游戏验收。
- 过去没得到的金币/药水和先前受限动作不会返还。天鹅绒项圈的回合计数随遗物对象一起退出监听；没有理由把旧计数转换为奖励。
- 原生NChooseARelicSelection支持遗物图片、手柄焦点、跳过与单选，但固定标题语义是选择/获得遗物。直接拿来做放下会误导。现有诸子观照EventOption已能带遗物HoverTips，可在同一事件页明确写“放下某物”，制作成本更低且语义正确。

## 节点、操作、界面与素材

如果仅作有条件表达机会，节点可放在既定第二幕第欧根尼Question页：玩家看到自己实际持有的合格遗物、其收益和限制，选择放下其中一件或保留。复用诸子观照背景、标准事件按钮、遗物原图与提示、原生移除反馈；无需新房间、NPC、敌人目标或动作动画。若成为主说，仍至少需要一枚主说静态图标及描边版，但本阶段不命名、不制作，因为主能力判决未通过。

选择成功后失去额外能量和原物，未来恢复原本金币/药水/出牌权限；拒绝保持双方。后继只可记录物品、实际放下、过去损失不返还和玩家明确说法，不认证自足或幸福。删除发生前须再次核对拥有关系，失败不得切换主说或消耗机会；真正实现还要验证多人、事件重入、移除订阅、保存和UI刷新。

## 反例与用途判决

完整反编译统计到102个RelicRarity.Ancient类型，三件已核实目标只是其中三件；远古稀有度不等于“额外能量加限制”，也不证明每局持有合格对象。现有EDGE010标为NoAdditionalGate，不能为了这个载体临时把人物关系改成库存门槛。

扩大到任意遗物也不成立：纯正面遗物被放下只剩无补偿损失，容易成为角色扮演税；复杂遗物可能已经改牌、给物、改槽位或写持久状态，移除不能安全回滚。按数值挑“亏得少”的遗物会把自足变成优化器。

**判决：不作为第欧根尼主要能力或采用条件。** 保留为以后合格对象恰好存在时的可选表达机会，前提是主能力另行成立；它不单独切换主说、不决定芝诺资格、不产生补偿奖励。当前不写原型、代码、ModelId或素材。

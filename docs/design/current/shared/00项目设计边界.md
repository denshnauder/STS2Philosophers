# 项目设计边界

## 三分钟摘要

- **当前结论：** 设计先于代码，但设计结论必须同时承担玩家操作、实际取舍、失败恢复和正式制作成本。
- **玩家流程：** 每个交付 Issue 完成一个可独立说明的玩家循环；部署后即可进入后续开发，试玩反馈另开 Issue。
- **核心取舍：** 复用基础设施，不让已有代码倒逼设计；保留历史证据，不让旧任务状态覆盖 Linear。
- **界面与素材成本：** 默认只使用原生界面、既有图标与少量静态图。柏拉图守灯与旅人继续只作设计实验。
- **已完成：** 当前设计、玩家事实、实现事实和研究归档已分入口。
- **准确下一步：** 对应人物任务只更新其唯一当前入口和确有必要的支撑材料。

## 不可混淆的证据层

1. 用户锁定的项目方向与限制。
2. 研究来源、解释争议与游戏创作之间的边界。
3. 候选设计及其反例。
4. 已实现并通过相关自动检查的内容。
5. 已完成构建、安全部署并可由玩家进入的内容。
6. 玩家之后提出的界面、文案、平衡与体验反馈。

自动检查只能证明实现符合已写规则，不能证明思想表达或乐趣成立；玩家尚未试玩也不能把已经安全部署的交付保持在未完成状态。

## 制作底线

- 优先复用战斗、卡牌、遗物、奖励、地图和标准事件界面。
- 不把纯文字原型成立等同于正式制作可行。
- 不默认 AI 美术能通过风格、来源、版权和可读性审查。
- 存档、公共状态、迁移和不可逆操作继续按高风险变化处理。

## 事件入口统一规则与迁移范围

开局观照直接接在先古之民之后，不占地图问号。其余全部哲学事件，包括固定、实践、第二幕观照、第欧根尼与斯多葛芝诺，只能在玩家进入真实地图问号且原生判定为事件时获得触发机会。路线、遗物、先前选择、战斗经历与间隔等仍是资格条件，不保证遇见；不额外生成节点，也不在战后或幕初返图时弹出事件。人物原有 Fixed／Question 业务机会语义保留，地图问号不等同于一律占用 Question 预算。

ENC-199 迁移实施前的 0.5.18：12 类 Question 已使用该入口；17 个固定／实践事件、第二幕观照、第欧根尼及斯多葛芝诺仍有额外房间入口，**该版本实现不符合要求**。0.5.19 迁移代码已通过纯逻辑、原生问号选择、实际内存保存／读取、失败重试及旧两层事件退出检查；部署与真实试玩分别核实，不把测试当作游戏内验收。以下人物文档中的历史战后或幕初固定出现说明不作为入口豁免。迁移不扩写人物玩法、奖励或新素材，复用原生事件界面；只改变遇见地点与必要的保存和旅行衔接。

已进入旧事件或已准备的奖励／旅行事务按保存的确切身份恢复，不能重新抽取或授奖。尚未进入的资格等待下一同幕合法问号；不得通过改写玩家存档、追加地图历史或伪造旅行完成来迁移。哥白尼只使用实际当前问号已有的两个合法出口。新原生事件结束返回当前节点的地图；已冻结的旧事务保留其原恢复目的地。开局观照的去重保护与事件即时奖励继续有效。

代码与原生自动检查通过、安全部署、真实游戏试玩分别报告；未实机验证不能称为游戏内验收。迁移后的完整页面文字流程在聊天中交付，由用户整理和审阅，不另建流程图文件。

详细规则见 [美术与制作约束](../../ProductionConstraints.md) 与仓库根目录 `AGENTS.md`。

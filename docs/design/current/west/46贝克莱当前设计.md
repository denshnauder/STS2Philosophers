# 贝克莱当前设计（ENC-133）

## 承接位置

- 主用途：内批。宿主是**洛克的主事件房间**，不新增问号、不占用第二幕问号、不推进主线幕数。
- 路线：笛卡尔开局 → 第一幕洛克〔贝克莱内批〕 → 第二幕休谟 → 第三幕康德／胡塞尔。
- 容量：开局之外每幕最多一个哲学事件，第三幕只负责一次收束；贝克莱与洛克共用同一房间，因此不破坏该容量。
- 旧存档：已完成洛克的存档不回插、不补发该段；只有新开一局创建的洛克记录才带贝克莱状态。

## 玩家流程

洛克的关键选择结算后，结果页多出「查看屏风后」。进入后是货栈后间：屏风遮住第二批货物，玩家只能选一种证据通道——

1. 伸手触摸；
2. 敲击听声；
3. 核对凭据。

选定通道后确认屏风后的货物，并在同一位置发现看货人藏起的第二件物品：先前的解释覆盖不了这个反例。此时给三个窄结论：

- 拒绝无物质支撑的解释（不宣布“没有物体”）；
- 要求第二观察者核对（花一次商店采购机会）；
- 保留感知范围，不对实体本身下结论。

结算后回到洛克结果页，可正常离开。三种结论都不改变路线节点，也不额外推进幕数。

## 实现与存档

- `BerkeleyPerceivedMarkState` 记录：观察通道、屏风下的第二件物品 ID、窄结论、已确认动作、是否关闭；严格版本与重放校验。
- 状态嵌套在 `LockeCargoIdentityState.Berkeley`，随洛克事件一起保存与恢复；`Inspecting` 标记当前是否处于内批段。
- 事件页与选项全部走中英双语键：`LOCKE_CARGO_IDENTITY.pages.RESULT_*.options.INSPECT_SCREEN` 与 `BERKELEY_PERCEIVED_MARK.*`。
- 旧档 `Berkeley` 为 null 时不显示入口；关闭后不再重复提供。

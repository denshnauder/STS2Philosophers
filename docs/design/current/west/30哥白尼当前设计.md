# 哥白尼当前设计

第31位，ENC-126，主用途实践。《换一个中心》正在实现，未交付。已读取 [PR #4](https://github.com/denshnauder/STS2Philosophers/pull/4) HEAD `cf2cf9a` 的第31人候选及审查，采用模型重排、剩余误差和真实择路代价，不将书面“路线记录”当作实际旅行。

依据《天体运行论》[I.9—10与作者序言](https://math.dartmouth.edu/~matc/Readers/renaissance.astro/1.1.Revol.html)：把地球运动纳入行星现象解释，会改变各运动间的关系和排列；不等同即时消除全部误差，也不以现代无条件真理代替当时的数学与天文学传统。奥西安德代序另有作者，不能把其假说工具论直接归于哥白尼。虚构行路表只作游戏转译，不承诺日心模型带来捷径、预知物资或统一科学方法。

## 出现与一个选择循环

第二幕，单一赫拉克利特竖琴，真实德谟克利特采纳且闭合、恩培多克勒已接受并闭合，仍在德谟克利特／LastFixed2、Q2已使用；普通非Boss战斗原生奖励结束安全返图后，完整原生可旅行集合恰有两个向前非Boss出口才出现。用公开`MapTravel.GetTravelablePointsFrom`，不能以`Children`代替。此用途是实践，不新增或占用Fixed／Question，不依赖待部署的培根，也不改当前学说。恩培多克勒邀请拒绝不符合。

两幅虚构行路表分别建议当前地图的出口A/B，并显示真实出口类型。玩家可以谢绝。参加后选择保留旧表或采用太阳参照：旧表直接检查剩余误差；新表须用三步重排观察者位移、行星运动、表观逆行，每步最多两个按钮，先纳入观察者或行星运动，不能继续以表观逆行作为不需解释的起点。保存玩家真实排列并显示当前次序，不把某一种说明顺序当作历史人物的唯一算法。

两种模型都需记录尚未消去的周期／星位误差，再决定按所选表真正出发或撤回。旧表对应A，新表对应B；实际调用原生旅行，承担该地图分支原有的正常代价，放弃另一边本次普通机会。新表无额外金币、卡牌或确定安全保证。撤回／谢绝保持普通地图自由选择。

## 保存、恢复与制作

保存种子、幕、来源坐标／房间／访问与地图历史长度、完整二出口坐标与类型快照、德谟克利特与恩培多克勒实例、模型与观测排列、剩余误差记录、准备／确认及确定出口。每个选择沿用准备→保存→提交→保存屏障。出发前重验同一原生地图身份与完整合法出口集合；集合漂移、坏状态或未知中断不重抽、不写地图边、不回滚坐标。

确定出口写入并验证原生/Ritsu存档后才完成事件，`NEventRoom.Proceed()`打开地图，立即锁旅行输入并等待原生`NMapScreen.TravelToMapCoord`。Proceed不自行弹出嵌套房间；原生旅行会清理房间栈。原生先保存目标坐标，再生成目标房间和历史，因此本事件Closed只代表确定／放弃，实际抵达需由目标坐标、访问增长、目标历史及正常原生房间共同证明。起点恢复重试同一目标；目标处已有正常证据不再次旅行；目标坐标已前移但房间未生成时交给原生加载恢复，不能凭坐标重复走或宣称已完成。普通目的房间不调用仅适用于事件房的PersistEventAsync。

复用现有事件页面、原生地图、旅行动画和公开API；不新增框架、地图节点、立绘、场景或自定义导航UI。检查新表四种排列与旧表、谢绝／撤回、各保存断点、集合漂移、确定目标只走一次及原生旅行保存时序；无渲染界面或实机整局的检查不宣称试玩通过。完成增量实现与推送后进入原有待部署批次。

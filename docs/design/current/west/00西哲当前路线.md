# 2026年10月30日：三幕承接与问号容量收束

这是本轮架构设计，取代下方旧文档中要求额外人物问号、第四幕或等待另定宿主的安排；不是已实现状态。用户要求将散点接成可玩链条，无法成立的独立任务移出 Todo。保留六位开局入口、七问题与现有存档；允许为新路线补节点和边，不再把旧图缺边视作禁止设计。

## 一局容量

- 开局仍在先古之民后，不占地图问号。开局的问题选择同时限定本局路线分支候选，不能将整张人物表加入通用随机池。
- 开局之后，第一幕最多一个哲学承接事件，第二幕最多一个展开事件，第三幕最多一个收束事件；每个都必须使用真实地图问号原生抽中的事件房间，不额外生成节点或战后弹窗。
- 同一行的第一／二／三幕是有序承接；不同行是跨周目替代方案，不相加。斜杠表示互斥选一。每个房间最多一位主人物及一位可选内批人物；内批共用该房间，不再消耗额外问号。
- 第一幕即允许现代问题重开。开局到现代人物的连接表达“同一问题的另一种处理”，页面需明确这层转换，不假造直接师承、历史对话或沿袭关系。相关中介以背景短说明保留，不强制玩家另遇多位人物。
- 第三幕只有一次兑现和收束，不再要求“康德→费希特→黑格尔→马克思”连续抽多个问号。不新增独立第四幕回响。回响只能是本次收束事件的结尾页。
- 某幕没有遇到合适问号、拒绝承接或选择保留原实践时，不强制补弹、不空降依赖后继。保留现有能力；后续实际事件可以对已发生的选择收束，但不能伪造已经遇见人物。链条可完成不等于每局保证抽到全链。
- 这些是新局实现目标；旧局按原事件和保存版本安全恢复。不得直接修改旧局的已消费机会或补发奖励。

## 具体解堵结论

- ENC-133 贝克莱：宿主确定为洛克的同一事件房间。洛克的关键选择后提供可选内批段；不创建追加问号、不额外推进主线幕数。保留既定内批用途。已完成洛克的旧存档不回插或补发该段；新局使用新事件版本。
- 马克思：通过“自律与历史”第三幕或“社会批判”第一幕进入，按进入问题采用对应内容版本。一局至多遇见一次。黑格尔〔存在〕不能冒充黑格尔〔历史〕前置。康德／费希特前移到第一幕是新分支安排，不直接篡改旧第三幕康德存档。
- 索绪尔、弗雷格：在亚里士多德开局的问题选择中提供现代问题重开分支，第一幕分别承担对应分支主节点。不是增加第七位开局人物，也不是直接启用旧的已退役边。
- 德勒兹：落在斯宾诺莎—谢林链的第三幕。无须先遇黑格尔，也不恢复旧黑格尔到德勒兹固定承接。
- 利科：确定为伽达默尔收束事件的结尾回响，不另造第四幕或第二个第三幕问号。原人物任务保留其回响交付范围，不要求独立主节点。
- 36张尚为 Todo 的人物任务在上表均有具体宿主或完整链条，因此本轮不凭“旧图无边”删除人物。取消的是这些人物的额外独立问号／第四幕方案；以后若某人物连同房内批或互斥分支都无法提供独特选择，再取消其独立交付任务并保留研究资料，不以文档交付冒充已完成玩法。

## 开发依赖和验收边界

表中的箭头是单局内容承接，不自动等于人物 Issue 的串行开发依赖。人物状态、文本、效果及测试可按既有开发顺序实现，使用明确的输入输出契约；在父节点尚未上线时不能声称入口已可玩。发布整条链时，核对所有实际必经节点已接入，第三幕每局最多一次人物房间，没有额外预算或强行弹窗。

图和事件系统需要支持“问题面＋人物阶段＋分支”而不只按人物姓名连线。对本轮已明确的边和宿主，DSH 可直接细化实现，不再以旧JSON没有边、旧Fixed/Question标签不同或缺第四幕为由等待Astra。需要修改通用触发预算时只在明确范围内实施，并验证旧档兼容；框架设计不代表这些代码已经完成。

上述新链的收益、代价和完整游戏页面由DSH逐事件展开并交用户审阅；不能仅凭人物名单相连宣称玩法验收通过。既有版本冻结与禁止部署限制仍有效。

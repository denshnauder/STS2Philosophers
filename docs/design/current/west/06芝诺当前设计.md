# 芝诺当前设计

## 第一幕制度问号修正（ENC-196，已实现待部署）

《命令的例外》与下文第三幕德性终点是芝诺的两种独立用途。玩家已明确第一幕Question应占用地图问号，并在事件结束兑现新遗物或改良；本次沿用城邦印章，不另做遗物图标或新Model。合法前置仍为柏拉图制度入口、单一城邦印章、第一幕未使用Question及既有实际路线；进入原生Unknown点并抽为Event时占用该节点，不再战后额外插入。

玩家核查管理员的无据优先请求，选择公开适用同一规程或提出可申诉的狭窄例外。最后正式公开质疑时，保留019已知记录及其020后继资格，同时选定当前印章改良；到结束确认立即生效并显示，不等下一幕。公开规程：每回合首次手动沿用已立规则的牌结算后获得3格挡；有条件例外：每回合首次手动打异类牌结算后抽1张，原有异类加费仍保留。本场首次立规则的牌不算沿用／例外；自动出牌和重复回调不发收益。前者支持规则同类组合，后者需承担异类加费换取手牌，两种改良互斥，不以战斗得失证明哲学正确。

谢绝或撤回不改良，保留原遗物与原有未提交后继处理。使用现有事件页、画像、遗物悬浮提示与原生格挡／抽牌；不新增场景、动画或常驻面板。结尾明确提示何时生效及保留的代价，取消“只有下一幕优先路线”的收益表达。

奖励随真实事件实例、已确认分支与关闭保存，原生遗物保存载体留一次性发放及战斗／回合回执；重复提交、实例矛盾或损坏载荷不重置。旧已结束芝诺记录不自动补奖励；旧未完成记录须显式兼容并保持文案与可领取事实一致。必须检查自然问号房间序列化及重载、战后不再新插入、改良生效前后、真实手动格挡／抽牌与自动／重复排除、原生保存读回和坏档，再构建部署。

0.5.16已通过上述纯逻辑及原生选择／房间恢复、真实费用与格挡／抽牌、原生遗物序列化和读回检查；Release、PCK及事件画像装载通过。当前尚未部署，未进行渲染界面或实机整局验收。

## 三分钟摘要

- **当前结论：** 芝诺是第欧根尼 Switch 后保证出现的第三幕终点，处理眼前印象、同意范围、实际行动和后来结果之间的关系；成功不反推判断正确。
- **玩家流程：** Switch 后至少完成一个非路线房间，系统在安全地图边界、Boss 前或离幕前兑现事件。玩家回看冻结的真实材料，然后保留、缩小、撤回理由，或在缺少合法材料时拒绝补写同意。
- **核心取舍：** 转向芝诺已经放弃第欧根尼完整结局；芝诺允许修订但保留公开历史，不发数值奖励，也不改变当前战斗能力。
- **界面与素材成本：** 一个标准事件和一张1600×900静态图；无新地图、敌人、动画、主说遗物或常驻面板。
- **已完成：** 状态、事务、严格编解码、旧档与损坏隔离、事件页面、触发、关闭续行、正式入口、素材、验证、构建和安全部署均已完成。
- **未完成：** 裁切、文字节奏、选择价值和平衡感属于之后的玩家反馈，不阻塞当前交付。
- **准确下一步：** 芝诺的新修改只由 Linear 的 Bug、Improvement 或 Design `Todo` 触发。

详细状态与设计证据见 [芝诺德性设计](../../ZenoVirtueDesign.md)，玩家流程见 `README.md`，实现事实见 `DEVELOPMENT.md`。

## 一次试玩脚本（ENC-92，2026年10月16日）

这份脚本留到愿意试玩时使用，不要求现在启动游戏。它合并九张旧票的重复步骤，不改变其结论，也不作为后续开发的闸门。本文只经过代码、中文文案与旧票的交叉核对，没有新增实机通过记录。

### 先选测试局

最短主线只走一局“转向芝诺”，串起两轮保存加载、去留页面、延迟出现、芝诺页面和退出恢复。要比较“停留”，需另一局或预先保留的独立测试副本；不要用同一局已经确认的路线反复改选。

| 测试局 | 用途与准备 |
| --- | --- |
| A：普通单人德性局 | 开局候选有苏格拉底时选“德性与幸福：审思砝码”；保留这条路线直到第三幕，第二幕若遇到“两项职责”则选“保留苏格拉底路线”并离开，不转入柏拉图节点。人物不在本次三人候选中就留到合适的局，不要求反复重开。当前正常流程没有主动撤离操作，第三幕应如实显示缺少可核对材料。 |
| B：停留对照 | 另一局相同路线，或已妥善备份、与A分开的未确认测试副本；只做下文第3步的停留分支并继续正常前进。 |
| C：旧档兼容 | 仅在已有对应历史备份时做；与A、B分开。旧局保存文件与对应附属文件一并备份，保留原件，不编辑JSON、不删标记、不拿主力存档试错。没有样本就记“未覆盖”。 |

### 主线八步

| 步骤 | 玩家操作 | 应看到什么 |
| --- | --- | --- |
| 1．先确认能加载 | A局在尚未进入第欧根尼／芝诺时，正常保存退出到主菜单，再继续游戏；随后再保存退出、继续一次。 | 两轮均能进入同一局，人物能力、进度和已有选择保留；不凭“保存成功”代替“能继续游戏”。 |
| 2．到第欧根尼 | 保持苏格拉底德性路线进入第三幕，幕初地图应出现“第欧根尼：去留”。在“回看已有材料”“停在这里”“了解芝诺的训练”之间查看并返回；进入确认页后先返回一次，再未确认退出重载一次。 | 只浏览不锁定路线、不发奖励；重载回去留首屏。缺材料就明说缺材料，不捏造撤离、药水或公开理由。确认页首项是返回；鼠标与手柄确认作用相同，取消键不代替哲学选择。没有手柄就把手柄项留作未覆盖。 |
| 3．确认互斥去留 | A局选“了解芝诺的训练”→“继续了解”→“确认转向芝诺”；在结果页保存退出、继续，再点“继续”。B局则选“停在这里”→“确认停留”，同样重载并离开。 | A保留转向，不能改成停留；B保留停留，本局不再出现芝诺。两边战斗能力都不变，既不发资源，也不同时拿到两个结尾。 |
| 4．等芝诺兑现 | A返回地图后先保存退出、继续一次，再完成一个普通非路线房间并处理完奖励／商店／事件。 | 单纯返回地图或读档不算完成间隔；普通房间结束后在安全边界出现一次“芝诺：同意的边界”，不吞掉原房间、奖励或其他人物内容。 |
| 5．看材料与页面 | 芝诺页选“回看转向来处”并返回，再选“继续辨明范围”；进入最终确认页前后各返回一次，未确认时退出重载一次。 | 回到材料页而不是把浏览当提交。当前无材料、无公开说法的普通局只允许“不作同意”，不能要求出现保留／缩小／撤回。材料、图片和按钮可读；不可逆确认默认落在返回项。 |
| 6．确认并重载 | 确认“不作同意”，到结果页后保存退出、继续两次；不要在结果页尝试重选。 | 始终回到同一结果，不能刷新结局、复制事件或重复发资源；没有真实材料就仍不补写事实或理由。 |
| 7．离开并继续 | 点芝诺结果页“结束路线”，回到原去向后再保存退出、继续，并正常前进一步。 | 地图能继续走；若由Boss门或离幕门触发，则继续同一个Boss入口或原离幕去向。芝诺不再重开，不改战斗主说。 |
| 8．只记三条感受 | 分别记下“转向失去了什么”“稍后出现是否值得等”“哪一页难懂或像多点一次”。有B局时再比较两个结尾。 | 记录实际感受即可；没有玩B局就不宣称完成去留价值比较。卡住、无意义或文案不清都可作为独立反馈，不需替哲学答案判分。 |

遇到第一次不能加载、卡死或状态矛盾就停在原现场，保留副本与日志，不删档、不靠重置路线继续“刷过”。意外在保存中断时不预判提交成功或失败，重载只能恢复同一事务；本脚本不要求掐时中断，普通UI无法稳定覆盖准备／提交之间的内部故障注入检查点。

### 只在有样本时补做

| 场景 | 最少补充操作与预期 |
| --- | --- |
| Boss前保证出现 | 只用已经具备合法预约且尚未兑现的独立Boss边界样本：应先完成一次芝诺，再进入原Boss。当前正式邀请在第三幕幕初，正常前进通常已在普通房间后兑现；A不能覆盖此兜底，没有样本就记“未覆盖”，不要求玩家找“直达Boss”按钮。 |
| 离幕与死亡 | 只在已有合法独立样本时补离幕兜底：尚未兑现芝诺就离幕时，应先兑现再续原去向。能自然覆盖的预约后死亡应随本局终止，不播放死后事件。不要为凑覆盖用控制台跳幕、伪造死亡或改档。 |
| 旧档C | 载入备份副本，核对原有能力与路线，再正常保存、退出和加载两次；状态应保留。已保存合法预约的应恢复同一预约，不能因旧档缺记录就猜成已转向；旧局新邀请资格另见附注。迁移格式是否正确由开发者只读检查，玩家只报告能否加载与状态是否一致。 |
| 开发入口 | 已有开发控制台且符合附注门控的独立测试局，可直达无材料芝诺，复用第5—7步。它不能覆盖正式去留、真实材料、自然延迟出现或Boss／离幕兜底，也不要求玩家配置控制台或重置状态绕过拒绝。 |
| 真材料、撤离与全部结局 | 当前普通UI没有主动撤离／公开说法生产链，不能按旧设计要求玩家找这些按钮。已有合法行动样本时可检查继续／撤离事实与“不重新同意”；保留／缩小／撤回还需后续生产说法链及权威校验目录支持，现在记“未覆盖”，不能改存档造样本。 |

### 失败时只留这些

记“步骤号＋所选按钮＋退出前后哪个时点＋预期／实际”即可；另留一张能看到事件标题、正文和按钮的截图。加载失败附错误画面；开发者排查时再取相近时间的游戏日志和对应测试存档及附属文件副本。涉及重复事件时附种子、幕和地图位置；不要求每一步录像或提交私人主力存档。

### 开发附注与覆盖对应

- 当前正式入口要求单人、第三幕（代码幕索引2）、`SOCRATES__VIRTUE_AND_HAPPINESS__CORE`与审思砝码教义仍一致；走完柏拉图转向后不能用这局声称覆盖该入口。`DiogenesStaySwitchEntryPolicy`接受合法上游事实，但当前普通生产路径未提供撤离机会与提交界面；它也不生成公开说法。合法旧事实只有在已经存在时才读取，不由脚本构造。
- `zenoassenttest`无参数：需现有开发控制台、单人第三幕、战斗外、单层房间栈、已完成普通房间后的安全返图边界；当前房间不能是幕初`MapRoom`或第欧根尼／芝诺。还要求`PreFeatureLegacy`载荷且无保留标记，合法的空`Current`载荷也会拒绝。它只创建显式`NoMaterial`开发记录，不重置既有局来绕过门控。
- `ritsurunprobe write`／`ritsurunprobe read`最小探针已在2026年9月26日获得两轮实机通过记录，本票不撤回该结论，也不要求重复探针；该证据不外推成共享状态迁移、芝诺SL或旧档兼容已实测。
- 旧`EventsSeen`合法marker在没有RitsuLib新槽时才迁入，后续正常保存写入新槽；异常或未知版本必须保留而不能猜成无材料。当前入口按实际现场和载荷资格判断，没有按存档年龄一律排除：恰停第三幕幕初`MapRoom`且路线／教义完整的旧局可创建邀请；途中普通房间不补邀请。新邀请与已有合法预约恢复分开记录，迁移和损坏隔离仍需对应历史／异常样本，正常A局不能替代。
- 覆盖去重：第1步与旧档C对应ENC-66／68；第2—3步对应ENC-54；第4步与兜底分支对应ENC-56；第5—7步及旧档对应ENC-55／61；开发入口对应ENC-62；第8步对应ENC-57；真实上游样本对应ENC-73。ENC-54／55／56／57／61／73已Canceled，ENC-62／66／68已Done；仅映射其历史检查内容，不恢复旧验收票、不把未测项记为通过。

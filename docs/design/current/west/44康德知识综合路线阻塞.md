# 康德知识综合路线阻塞说明

## 现状

图上保留的知识与怀疑路线是：

- `WESTERN_EDGE_012`：第一幕 Question／Switch，苏格拉底知识 → 塞克斯都。
- `WESTERN_EDGE_013`：第二幕 Fixed／Adopt，塞克斯都 → 笛卡尔知识，要求 012。
- `WESTERN_EDGE_014`：第二幕 Question／Revise，笛卡尔知识 → 休谟，要求 013。
- `WESTERN_EDGE_015`：第三幕 Fixed／Adopt，笛卡尔知识 → 康德知识，要求 014。

按图语义，完整链路应是：

`苏格拉底知识 → 012 塞克斯都 → 013 笛卡尔知识 → 014 休谟 → 015 康德知识`

## 实际生产行为

- 塞克斯都事件只保留第一幕问号占位，`SextusOpposedAppearancesState.QuestionSlotReserved = true`，生产事件没有应用 012，也没有把当前节点切到塞克斯都。
- 笛卡尔事件在苏格拉底处触发，选择拒绝第二幕固定选项；生产事件没有应用 013。
- 因此 013 永远不满足“012 已完成”，014、015 也随之不可达。
- 现有测试中出现的“应用 013 后继续”的路径是测试辅助，不是生产可达路径；不能据此声称康德知识综合已交付。

## 可选方案

### A. 补齐原图链路（推荐，但需产品确认）

按原图实现：

1. 塞克斯都事件完成 012，并允许进入塞克斯都节点。
2. 笛卡尔事件在塞克斯都触发，完成 013，进入笛卡尔知识节点。
3. 休谟事件在笛卡尔知识节点完成 014，保留在笛卡尔知识节点。
4. 康德知识事件在笛卡尔知识节点完成 015，进入康德知识节点。

需要同步修改：

- 塞克斯都状态、流程、事件和原生测试：从“只占位”改为真正完成 012。
- 笛卡尔事件的触发节点、固定选项和状态：从苏格拉底处拒绝固定选项，改为塞克斯都处应用 013。
- 休谟/康德知识的触发、选择、路线状态和本地化文案。
- `tests/ModLogicChecks` 与 `tests/NativeRuntimeChecks` 中依赖“苏格拉底处笛卡尔”的既有断言。
- 旧存档兼容：已经停在苏格拉底或已拒绝笛卡尔的存档需要迁移策略。

影响范围覆盖四个事件和既有测试，不能只新增一个康德事件或手工应用 013 来完成。

### B. 把康德知识挂到其他既有边

图上的 `WESTERN_EDGE_015` 是唯一指向康德知识节点的边；其他康德边分别进入自由或自我节点，槽位和语义都不匹配。改源节点或槽位会替换既有问号/固定窗口，不能作为未确认的实现方案。

### C. 新增第四幕或新边

超出当前三幕结构和“不得伪造图边”的约束，不采用。

## 当前结论

- 未修改 012/013/014/015，未重新加入康德知识事件，未伪造可达路径。
- 康德知识综合仍阻塞在 012/013 的生产语义上；需要人工确认方案 A 的路线与旧存档处理后再继续。
- 塞克斯都、笛卡尔、休谟和康德知识的现有交付状态不能按“完整链路可达”宣称验收。

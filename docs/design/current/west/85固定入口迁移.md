# 固定入口迁移：先古之后的幕内固定事件

## 问题

Sol 在 ENC-123（马基雅维利）指出：现行实现把所有房间都挂在「地图问号」上，而新口径要求每幕先古之民结束后接本幕固定哲学事件。

证据：40+ 个房间补丁的 `InsertAtBoundaryAsync` 都是空实现；实际插入只发生在 `NativeQuestionNodeEvents`，而 `IsEntry` 硬性要求 `CurrentMapPoint.PointType == Unknown`。框架里唯一的先古后插入点是 `NeowProceedPatch`，只覆盖第一幕先古（Neow）。

## 已落地的框架

1. `ActFixedEntryPolicy`（纯逻辑，`src/Philosophy`）：拦截条件为运行中、事件房、当前事件是先古、事件已结束、幕索引 1 或 2、本幕尚未进入过固定事件、固定边可采纳、房间可用、单人。
2. `ActFixedEntryCatalog`（`src/Events`）：节点 id → 选择器。房间自行登记，选择器负责建立/校验自身状态并返回事件模型。
3. `NeowProceedPatch`：`CurrentEventKind` 新增 `Ancient`；第二、三幕先古结束时，先尝试 `ActFixedEntryHost.TryPrepare`，命中则 `MarkPreFinished` → 持久化 → `EnterRoomWithoutExitingCurrentRoom`，未命中则完全交还原版 Proceed。
4. `ActFixedEntryHost`：按当前旅程取本幕可采纳的 Fixed 边，只处理已登记节点；`VisitedEventIds` 与房间自身状态守卫防止重复进入。

首个迁移房间：马基雅维利（ENC-123）。`MachiavelliFloodPreparationPatch.TrySelectFixedEntry` 只走幕内固定入口：第二幕、旅程在卢梭、046 可采纳、未琢之石可提议、后幕遗物资格成立、状态一致，缺一不插入；原生问号路径保持原样，两条入口互不借预算。

## 第三幕固定额度（已修）

`WesternRouteGraph` 原来在 Fixed 采纳时要求 `LastFixedAct < 3` 且采纳后自增，结果三幕最多只能采纳两次固定：第三幕固定只有在第二幕固定被拒时才能进入。这与「每幕先古之后都有一个固定位置，前置满足就触发、不满足就空着」不符。

现在的规则：

- 采纳固定边要求 `LastFixedAct <= 3`，采纳后 `LastFixedAct = min(3, LastFixedAct + 1)`；第三幕采纳后仍停在 3，因此第三幕房间的既有后置判定（`LastFixedAct == 3`）不变。
- 拒答固定边接受 `expectedAct` 等于当前或下一个固定位置，并把位置推进到 `expectedAct`；同一幕重复拒答被拒绝，不会一次跳过两幕。
- 完成判定与保留结局改为 `LastFixedAct >= 3`。
- 27 个第三幕房间的固定门从 `LastFixedAct == 2` 放宽到 `>= 2`：第二幕固定被采纳后（位置 3）第三幕固定仍可出现；第二幕固定被拒时（位置 2）同样可以出现。
- 完成后（`IsComplete`）不再提供任何固定边，第四幕回响仍然不可用。

于是「第一幕固定 → 第二幕固定 → 第三幕固定」在同一条合法路线上可以连续采纳，样例链 065（第一幕本瑟姆）→ 066（第二幕密尔）→ 056（第三幕阿伦特）已作为逻辑检查固定下来；前置不满足时该位置空着，不影响默认主线。

## 第二轮：边界选择器统一入口（当前实现）

上一轮只登记了马基雅维利一个房间。现在先古边界的选房不再逐房间登记，而是复用地图问号那条路由链：

- `FixedEntryScope`：只在「先古刚结束、尚未进图」的选房窗口内生效。
- 作用域内 `NativeQuestionNodeEvents.IsEntry` 接受先古房间栈（不要求 `MapPointType.Unknown`），`HasCompletedCombat` 视为成立——这两个只是插入锚点，房间自己的幕门、前驱边、遗物、已存状态与关闭状态仍然全部生效。
- `NativeQuestionNodeEvents.TrySelectAtActBoundary`：先恢复已存房间（`TryResumeExisting`），否则用 `TrySelectRoutedRoom(run, shared, carrier: null, fallback: null)`。carrier 为空时所有问号类型分支天然返回空，只有拥有本幕固定边、且自身前置成立的房间会应答。
- `ActFixedEntryHost.TryPrepare`：仅第二、三幕（索引 1、2），且旅程的固定位置正好是本幕（`LastFixedAct == 幕号`）时调用上面的选择器；返回空则完全交还原版 Proceed，不插入、不改状态。
- 问号路径不变：`ModifyNextEvent` 仍走同一条 `TrySelectRoutedRoom`，只是 carrier 非空。

## 幕门口径

- 第二幕房间：`LastFixedAct <= 2`（第一幕固定已采纳后为 2；第一幕没有固定事件时为 1，都应能进）。
- 第三幕房间：`LastFixedAct >= 2`（第二幕固定已采纳后为 3；被拒或缺失时为 2，都应能进）。
- 采纳后位置封顶 3，第三幕房间的后置判定不变；完成后不再提供固定边。

## 仍未验证

没有原生用例证明「真实先古事件 Proceed → 固定房间」的完整链路（需要构造第二幕先古房与对应遗物/旅程）；因此本框架提交不声称任何人物票已具备默认固定主线。

## 第三个房间：斯宾诺莎（原生已证）

斯宾诺莎（第二幕固定，边 023）原先要求 `LastFixedAct == 1` 且 `FixedActTwoResolved = LastFixedAct >= 2`，等于「第一幕一旦有固定事件，第二幕固定就被判为已用」。现在：

- `FixedActTwoResolved` 只在 `LastFixedAct > 2` 或第二幕固定被明确拒绝时为真。
- 路线一致性接受 `LastFixedAct` 为 1（第一幕没有固定事件）或 2（第一幕固定已采纳）。
- 原生用例 `ActBoundaryFixedEntryNativeChecks`：第二幕、旅程在笛卡尔自我节点、固定位置 2、思维透镜在场，`ActFixedEntryHost.TryPrepare` 直接选出斯宾诺莎房并持久化可用状态；把位置改为 3 后同一入口返回空，不重复插入。
- 选择链在边界不读地图岔路（`fork` 仅在 carrier 非空时计算），因此不依赖问号节点存在。

这一步证明「先古边界 → 固定房间」的框架可用；其余房间仍需按同样口径逐个迁移（每个房间的 `FixedAct*Resolved`、路线一致性里的固定位置断言、以及是否需要「跨幕战斗之后」这类问号锚点）。

## 第四个房间：卢梭节点的共享位置（原生已证）

卢梭的历史与权力节点在第二幕有两个固定候选（马基雅维利、沃斯通克拉夫特），由种子决定谁先开这个位置。边界入口原先直接走普通选择链，谁在链上靠前谁赢，种子规则被绕过。现在边界先问 `TrySelectRousseauSecondAct`，再由普通链兜底。

同一轮还补了两处边界口径：

- 六个第二幕房间的路线一致性接受固定位置 1 或 2（奥古斯丁、德谟克利特、休谟、马基雅维利、奥卡姆、沃斯通克拉夫特）。
- `NativeQuestionNodeEvents.CombatCount` 在边界窗口内把「本幕已完成战斗数」报为至少 1（真实的 `HasCompletedCombat` 之前已如此）；房间自身的前置人物、遗物、路线事实仍必须成立。60 个补丁统一改用它。

原生用例现在覆盖两个场景：斯宾诺莎（笛卡尔节点、思维透镜）与卢梭节点共享位（未雕刻石），都断言无问号选出、状态可持久化、位置用尽后返回空。

## 第三幕与「战斗之后」锚点

- `HasCompletedCombatAfter` 在边界窗口内改为跨幕查找：本幕尚无任何历史，前置人物与其后的战斗都可能发生在前一幕。窗口外行为不变。
- 牛顿的 `FixedActThreeResolved` 不再用 `LastFixedAct >= 3`（采纳第二幕固定后位置就是 3，会把第三幕锁死），改为只看第三幕是否被明确拒绝。

牛顿本身仍要求「塞克斯都、重建后的笛卡尔都已关闭、第一幕问号已解、第二幕固定被拒绝」这一整串问号路径事实，因此他不在默认主线上，属于设计问题而非入口问题，留给 Astra 定夺。

## 全图不变量：每个固定边在本幕位置上都可采纳

`WesternGraphChecks` 新增一条覆盖全图的断言：对每条 `enabled` 且 `Slot == "Fixed"` 的第二、三幕边，构造「旅程停在该边起点、固定位置等于本幕序号」的状态，断言这条边出现在 `GetEligibleEdges(state, "Fixed")` 里。罗尔斯与阿伦特的房间尚未实现，暂时排除。

这条断言把「槽位算术是否把某个人物锁死」从逐房间排查变成一次全量检查：任何新加的固定边只要被 `LastFixedAct` 判定挡住，逻辑测试立刻失败。

## 采纳后位置

第二幕房间采纳固定边后位置会变成 3（从 2 采纳）或 2（从 1 采纳）。五个房间的「已采纳」一致性原先只认 2，导致从默认线（第一幕已固定、位置 2）采纳后立刻判为不一致：奥古斯丁、德谟克利特、休谟、奥卡姆、沃斯通克拉夫特现在接受 2 或 3。

## 仍被问号事实挡住的房间（待 Astra）

- 奥古斯丁：一致性要求 `ResolvedQuestionActs.Contains(1)`，默认线第一幕没有问号，因此他不在默认主线上。
- 牛顿：要求塞克斯都关闭、重建后的笛卡尔关闭、第一幕问号已解、第二幕固定被拒绝。
- 以弗所/普罗提诺、莱布尼茨、培根、安瑟尔谟等第三幕房间同样依赖问号路径状态（关闭的前置事件、`ResolvedQuestionActs`）。

这一类不是入口缺陷，是「固定位到底要不要以问号为前置」的设计问题。

## 结构性缺口：固定线在第三幕断掉（2026-10-30 实测）

把「只用固定边、不碰任何问号」的三幕链在全图上穷举一遍：

- 第一幕固定边 11 条，其中只有 3 条能接上完整的固定三幕链；
- 第二幕固定边的落点里有 14 个没有第三幕固定后继：奥古斯丁、罗素、皮尔士、列维-斯特劳斯、谢林、黑格尔、拉康、萨特、海德格尔、梅洛-庞蒂、霍克海默、福柯、马基雅维利、阿奎那。

也就是说：即使入口层完全正确，玩家在第一幕选了「本瑟姆」以外的多数固定人物，第二幕走完就再也没有第三幕固定事件可进——这正是「默认三幕完整」验收一直过不了的结构原因，不是某个房间的判定写错。

两条出路，都需要设计定夺：

1. 给这 14 个落点补第三幕固定边与房间（内容量大，且第三幕人物是否够分是设计问题）；
2. 承认第三幕固定事件按「遗物/路线资格」选择、不要求 `from_node_id` 连续（改动 `WesternRouteGraph.IsEligible` 的语义，影响所有固定边）。

## 问号结算与固定位置是同一字段（2026-10-30 实测，未改）

`WesternJourneyState.LastFixedAct` 同时承担两件事：

1. 已用固定位置的序号（`TryApply` 固定分支 `+1`）；
2. 问号结算的幕号（`TryApply` 问号分支 `ResolvedQuestionActs.Add(state.LastFixedAct)`、`IsEligible` 里 `edge.Act <= LastFixedAct`、`TryDecline("Question")` 比对 `LastFixedAct`）。

后果：第二幕在位置 2 采纳固定边后位置变 3，此后本幕问号会被记成第三幕；`RousseauConsentFlow` 这类要求「第二幕问号已解」的状态随即判为不一致。

试改（按 `edge.Act` 记账、`IsEligible` 用 `Contains(edge.Act)`）会让一条现存的、被测试固定的规则失效：**第一幕没接受的问号可以在第二幕作为「后来的反思」重新出现**（`WesternGraphChecks` 的 "An unaccepted earlier problem can return as a later reflection"）。按幕记账后它被永久关闭。

所以这不是单纯的 bug 修法，而是一个二选一的设计决定：

- **A. 保留反思规则**：问号按「位置」记账，则「第二幕问号已解」的判定必须改用真实幕号（需要状态里新增 `CurrentActIndex` 或等价字段，并处理旧档）；
- **B. 按幕记账**：语义更干净，但放弃反思规则，并要迁移旧档里按位置写下的 `ResolvedQuestionActs`。

已回退试验改动，逻辑测试保持全绿。

## 问号结算：位置与幕号同时记录（已修）

上一节的两个选项里，实际采用的是「A 的轻量版」，不需要新字段：

- 问号结算时同时写入**位置**与**边的幕号**（两者相同时只写一次）。位置继续支撑「第一幕没接受的问号可在第二幕作为后来的反思重新出现」，幕号让「第二幕问号已解」这类判定在本幕固定已采纳（位置 3）时仍然成立。
- `RousseauConsentState` 的三处 `LastFixedAct == 2` 改为 `is 2 or 3`：第二幕问号在本幕固定采纳后仍然有效。
- 新增回归用例复现 Sol 的序列：019（第一幕问号）→ 位置设 2 → 020（第二幕固定，位置升到 3）→ 021 仍在问号候选里，结算后 `ResolvedQuestionActs` 同时含 2 与 3。

### 样板路线的实测阻断（经验与自我，已回退）

按上一节样板改：新增 act 2 固定边 091（笛卡尔→洛克）、027（洛克→休谟）移到 act 3、休谟房间幕门放宽到第二/三幕、样例 08 改走 026→093→028。结果暴露一个更硬的约束：

**房间的「完成边」是写死的单一 `edge_id`**（休谟房完成 `WESTERN_EDGE_027`）。而设计允许同一人物在不同分支出现在不同幕：问号转线后休谟在第二幕、默认主线在第三幕。同一个房间要用同一个 `edge_id` 完成两个不同幕的到达，第二幕那次会把第三幕的边提前记成已完成，第三幕就不再出房间。

要真正落地，房间必须按「当前幕」选择自己的完成边（例如 `CompletionEdgeId(act)` 或按幕查表），而不是常量。这涉及每个房间的状态类与流程类，是结构性改动，不是改一条 JSON 能解决的。

已回退本次改动，逻辑测试恢复全绿。下一步应先做「房间完成边按幕选择」的通用机制（先在一两个房间试点），再回来补路线的边与幕标注。

### 按幕完成边的试点结果（经验与自我，已回退）

按「房间按幕选择完成边」改到一半，暴露出第二层冲突：**同一入口的多条路线在边界上互相竞争**。

笛卡尔节点同时是两条路线的第一幕：经验与自我（→洛克）与自然与生成（→斯宾诺莎）。给洛克加 act 2 固定边后，在 act 2 位置 1、持有斯宾诺莎石头的旅程里，洛克房间也会命中并抢在斯宾诺莎之前——原有用例立刻红。

触发上下文里没有「本局走的是哪条路线」的信息（只有节点、位置、战斗数），所以补一条入口→第二幕人物的边，会同时改变其它路线的选择结果。要先有路线归属（遗物/教义/开局问题）进入触发上下文，才谈得上按幕完成边。

已回退全部改动，逻辑与原生套件恢复全绿。下一步的顺序应是：
1. 把「本局路线」写进共享状态（开局问题已能确定方向）；
2. 触发上下文暴露该路线；
3. 房间按「幕 × 路线」解析完成边；
4. 再补路线表里的边与幕标注。

### 路线归属其实已经有了（2026-10-30 复核）

上一节说的「缺路线归属」不准确，先更正：开局选择时 `WesternEntryPolicy.RecordObtained` 已经写下三样东西——

- `CurrentDoctrine = { ThinkerId, DoctrineId }`，`DoctrineId` 就是入口遗物（如 `DESCARTES_THINKING_LENS`）；
- `RouteTags = ["WESTERN", problemId]`；
- `WesternJourney.CurrentNodeId = "{thinkerId}__{problemId}__CORE"`。

所以「本局走哪条路线」是可知的，缺的是**触发上下文没有把它传下去**，以及**图里的边没有按路线区分**。

真正的结构性冲突在这里：笛卡尔节点上同时挂着 023（笛卡尔→斯宾诺莎，act 2）和设计要求的 091（笛卡尔→洛克，act 2）。而设计表里「自然与生成」的入口是赫拉克利特，不是笛卡尔——023 是从旧网状关系留下来的边，起点人物与路线表不符。

因此修法不是加路线字段，而是**按路线表重挂每条固定边的起点**：023 应改为赫拉克利特→斯宾诺莎，同时把斯宾诺莎房间的 `SourceNodeId`、入口遗物条件与相关用例一起迁移。每迁移一个人物都要动：边的 `from_node_id`、房间的源节点常量、房间的入口遗物判定、以及引用该节点的逻辑/原生用例。

这条迁移可以逐个路线做、互不干扰，但每条都要成套改，不能只改边。

### 「自然与生成」迁移实测（2026-10-30，已回退）

按路线表加 094（赫拉克利特→斯宾诺莎，act 2），并把斯宾诺莎房间的遗物与教义判定从「笛卡尔透镜」扩到「赫拉克利特竖琴」。逻辑测试立刻红：

`The real Anaximander route selects its question without a completed-combat prerequisite.`

原因：赫拉克利特节点在第二幕、持竖琴时，同时满足阿那克西曼德（内批问号）与斯宾诺莎（新固定入口）。现有的问号选择器与测试都假定「一个节点 + 一幕只有一个合格路线」，并列路线一来，选择结果就变了。

所以并列入口不是加边就能上的，必须先给选择器一张**显式的路线优先级表**（同一节点同一幕有多条合格路线时按什么顺序取），并让测试按该表断言。已回退，两套件恢复全绿。

## 根本歧义：二十条路线、八个入口、七个遗物

把路线表的「第一幕先古后固定」列按入口归并：

| 入口 | 路线数 | 路线 |
| --- | --- | --- |
| 笛卡尔·主体 | 5 | 经验与自我、自律与历史、现象与解释、具身知觉、无意识与规范 |
| 苏格拉底·德性 | 3 | 意志与价值、个体承担、后果与自由 |
| 亚里士多德·语言 | 3 | 形式语言、日常言说、结构与排除 |
| 卢梭·历史 | 3 | 教育与处境、社会批判、谱系与权力、社会知识（含「卢梭」入口共 4 条） |
| 柏拉图·制度 | 2 | 制衡与公正、同感与公共行动 |
| 苏格拉底·知识 | 2 | 科学模型、可错探究 |
| 赫拉克利特·存在 | 1 | 自然与生成 |

一共 8 个入口、20 条路线，而入口遗物只有 7 种（每个问题一种）。**笛卡尔入口的 5 条路线共用同一个节点、同一件遗物、同一个问题**，游戏状态里没有任何字段能区分它们。

这就是「默认三幕完整」一直过不去的根本原因：不是边没挂对，而是**同一入口的多条默认主线在设计上无法区分**。任何一条边挂上去，都会和同入口其它路线抢同一个位置——前四轮实测的四种撞墙（洛克、休谟、按幕完成边、赫拉克利特→斯宾诺莎）都是这一件事的不同表现。

### 需要设计决定的一件事

同一入口的多条路线，靠什么在开局确定？

1. **开局多选一**：入口事件在获得遗物后再给一次「本局方向」选择（如笛卡尔入口给 5 个方向），把选择记进 `RouteId`；固定边按 `RouteId` 过滤。改动集中在开局事件与选择器，不动二十条路线的边。
2. **首幕固定事件内选择**：入口人物房间的选项决定方向（笛卡尔房选「我思」→经验与自我，选「身体」→具身知觉……）。内容改动大，但玩家感知最自然。
3. **合并路线**：把同入口的多条路线合并成一条，用第三幕的二选一表达分歧（如经验与自我 = 洛克→休谟→康德/胡塞尔）。改动最小，但会减少默认主线的条数。

我倾向 1：实现最小、可测试、不动已有内容，且能立刻让二十条路线各自可判定。选定后我可以一次把边全挂上并按 `RouteId` 过滤，不再逐条撞。

## 路线作用域已可执行（2026-10-30）

`WesternJourneyState.RouteId` 与边上的 `route_ids` 已经生效：

- `RouteId` 为空（旧档、未设置）时，所有边照旧开放，旧档行为不变；
- `RouteId` 有值且边声明了 `route_ids` 时，只有命中的路线能看到该边；
- 边不声明 `route_ids` 时对任何路线都开放。

第一条实际作用域：`WESTERN_EDGE_023`（笛卡尔→斯宾诺莎）标为 `["NATURE_AND_BECOMING"]`，并有回归用例证明「旧档仍可见、本路线可见、其它路线不可见」。

这解开了上一轮的死结：同一入口的多条路线不再需要抢同一个位置，只要每条边声明自己属于哪条路线。剩下唯一没定的仍是「`RouteId` 在开局怎么写」——即上一轮那三个方案里的哪一个。选定前，新局不设 `RouteId`，行为与今天完全一致。

### 第二幕「教育与处境」通过（2026-10-30）

卢梭 → 沃斯通克拉夫特 → 波伏娃 也走通了，但过程中查出一个真问题：`042`（沃斯通克拉夫特→波伏娃）原本 `required_edge_ids: ["WESTERN_EDGE_041"]`，而 `041` 是**第二幕问号**（沃斯通克拉夫特→密尔）。也就是说「第三幕固定波伏娃」被挂在一个问号后面，默认主线根本走不到——审计里把这条记成「完全正确」是错的。

按路线表：第二幕问号密尔是另一条分支，不是第三幕固定的前置。已去掉该前置，并在 `interpretation_boundary` 写明。

这条也说明「默认三幕完整」这个判据必须逐条用测试走一遍，不能靠对照表目测：`040`/`042` 的幕号和节点都对，前置却是错的。

### 结构障碍：`terminal` 节点不能做中间站（2026-10-30）

试「自律与历史」（笛卡尔 → 康德 → 黑格尔）时撞到一条硬规则：

`IMMANUEL_KANT__SELF_AND_OTHER__CORE`、`IMMANUEL_KANT__FREEDOM_AND_INSTITUTIONS__CORE` 都是 `terminal: true`，而 `IsEligible` 在固定槽位要求 `!IsComplete(state)`，`IsComplete` 又要求当前节点是 `terminal`。于是**任何以康德为第二幕的路线，都无法从康德再交接到第三幕**——位置一到 3，节点是 terminal，固定边立刻全部关闭。

同样的问题会出现在所有「既是某条线的收束、又是另一条线中间站」的人物上（康德、黑格尔、波伏娃、维特根斯坦、杜威、库恩……）。

`terminal` 现在是**节点级**属性，但设计需要的是**路线级**：同一个人物在这条线是终点、在那条线是中间站。修法有两条：

1. `terminal` 改成按路线判定（节点 + `RouteId` 决定），`IsComplete` 相应改签名；
2. 给「中间站」用的节点单独建非 terminal 节点（同一人物两个节点）。

我倾向 1：语义正确、不复制内容；2 会让节点数膨胀且容易挂错。

在此之前，「自律与历史」这类以 terminal 人物为第二幕的路线都走不通，这与前面「同入口多路线」是两个独立的结构障碍。

### `terminal` 已改成路线级（2026-10-30）

`IsComplete` 现在多看一眼路线表：位置满三幕、节点是 `terminal`，**并且本路线已经走到自己的第三幕人物**，才算结束。于是同一个人物可以在一条线收束、在另一条线做中间站。

依据就是 `config/western_mainlines.json` 里的 `act_three_figure`——不需要新字段，也不需要复制节点。

「自律与历史」因此走通：笛卡尔 → 康德（`095`）→ 黑格尔（`096`），两条边都归 `AUTONOMY_AND_HISTORY`。走通数从 2 变成 3。

另外把 `WesternGraphChecks` 里「每条固定边在自己那一幕必须开着」的不变式改成按边声明的路线取 `RouteId`，否则带作用域的边会被误判为不可见。

| 路线 | 第二幕边 | 第三幕边 |
| --- | --- | --- |

### 走通数 8 → 15（2026-10-30）

又补八条：自然与生成、个体承担、制衡与公正、后果与自由、同感与公共行动、社会批判、谱系与权力、科学模型。加上此前七条，共 15 条默认主线三幕不走问号走通。

过程中定了两条作用域规则，写进代码注释：

1. **作用域边对旧档不可见**：`RouteId` 为空的存档看不到只属于某条路线的边。否则新内容会改变旧档的问号选择——实测就是这么撞上阿那克西曼德那条用例的。
2. **公共交接边不加作用域**：`023`（笛卡尔→斯宾诺莎的旧投影）、`093`（洛克→休谟第二幕到达）、`040`/`042`（卢梭线）保持无作用域，因为既有房间与样本链依赖它们；路线专用边另开新号（如 `110` 赫拉克利特→斯宾诺莎）。

另外把「完成判定」放宽到路线的**收束人物**也算终点（经验与自我走到康德即合法收束），否则带路线的样本链会被判成「还没走完」。

### 走通数 15 → 19（2026-10-30）

补完三条：意志与价值（`150`/`151`）、日常言说（`152`）、社会知识（`140`/`141`）。

两处需要新约定：

1. **同一人物连任两幕不算交接**：日常言说的第二、三幕都是维特根斯坦，中间没有可交的边。走通判据因此允许「下一幕还是同一人物」时跳过该幕——这不是缺边，是设计本来就没有事件。
2. **缺节点的人物先补节点再连边**：叔本华原本有房间状态（`SchopenhauerWillDenialState`）却没有图节点，补了 `ARTHUR_SCHOPENHAUER__VIRTUE_AND_HAPPINESS__CORE` 并把节点实践表从 80 条扩到 81 条（该房间自己结算，节点不加通用奖励）。

### 路线身份有了第一个真实来源（2026-10-30）

上一轮留下的「`RouteId` 在开局怎么写」现在有了一个不需要新界面、也不需要设计拍板的来源：**第一幕问号**。

- `Start` 记住 `EntryNodeId`；
- 第一幕问号被采纳时，如果恰好只有一条路线「同入口 + 第二幕人物就是这个问号的目标」，就把 `RouteId` 写成它；
- 多于一条（例如笛卡尔入口的胡塞尔同时属于「现象与解释」和「具身知觉」）就不写，保持旧行为，等更明确的选择。

这与路线表的措辞一致（「第一幕问号洛克转线后……」），并且只在玩家真的走了那条问号时才生效——没有问号的默认主线仍然不设 `RouteId`，那一步仍需要设计决定。

用例：笛卡尔局采纳 `026`（第一幕问号洛克）后，`RouteId` 变成 `EXPERIENCE_AND_SELF`，第二幕随即开出洛克的 `093`。

### 第二幕房不再「只在第一幕开门」（2026-10-30）

原生边界用例暴露了一个比缺边更严重的问题：**路线走通不等于局内能开房**。制衡与公正的第二幕是孟德斯鸠，可孟德斯鸠房写死「第一幕、位置 1」，所以到了第二幕边界根本不会被选中——测试全绿，玩家看不到。

修法（孟德斯鸠、斯密两间先做模板）：

1. 房间状态加 `ActIndex` 与 `EdgeId`：它现在知道自己占第几幕、该提交哪条固定边（第一幕问号仍是 `051`/`054`，路线第二幕则是路线自己的边）。
2. 触发策略加 `RouteAct`：只有「本局路线把这位人物放在第 N 幕」时，第 N 幕边界才接受这间房。
3. 补丁从路线表读出 `RouteAct`，据此选边、建状态、算位置。

顺带修掉两条复制粘贴的日志：孟德斯鸠和斯密的房间都在打印「Presenting Mill's harm question」。

原生用例现在覆盖四条真机边界：斯宾诺莎（笛卡尔，第一幕位置 1/2）、孟德斯鸠（制衡与公正第二幕）、斯密（同感与公共行动第二幕）。

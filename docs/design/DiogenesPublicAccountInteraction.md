# 第欧根尼公开说明交互与恢复线框

## 状态与制作判决

本页把第欧根尼公开说明候选的 A—F 页面落实为鼠标、键盘/手柄焦点和退出读档恢复规则。D143先形成纸面规格；D144随后只读核实当前本机游戏程序集，确认默认焦点、运行时换图和嵌套事件入口的实际 API，并确认取消回调与事件页面存档不能依赖原生事件。

路线只有两个**计划出现时点**，即第二幕第欧根尼和第三幕回看/去留。D144确认标准事件节点公开提供运行时换图，因此当前制作方案收束为两个事件实例：第三幕在同一事件的Fz页切到芝诺图，不再为换图预留第三个连续事件。换图状态不是存档字段，恢复时必须由已提交的路线状态重新应用；如果最小实现无法稳定取得节点或加载纹理，安全降级仍是在第欧根尼图上完成中性说明，不增加自制场景层。

## 输入一致性

### 鼠标

- 只有可见且启用的选项可点击；按钮边界不得与正文或图像热区重叠。
- 双击确认只接受第一次回调；第二次读取已提交状态并拒绝重复写入。
- 返回只导航，不通过“先写再回滚”模拟无变化。

### 手柄与键盘

- 上下移动只遍历当前可见选项，隐藏分支不保留焦点。
- 每次进入新页都重新落到表中初始焦点；返回上一页也回到安全项，不记住之前的破坏性焦点。
- 确认键与鼠标点击调用同一个动作；不能存在手柄专用提交路径。
- 取消键若不能被原生 API 安全捕获就保持无动作；显式返回永远存在。

### 焦点变化

动态理由不会在当前页异步改变，所以选项列表在页面显示期间固定。分辨率、语言或输入设备切换后，若当前焦点项消失，焦点回到第一项安全返回；不能自动落到相邻提交项。

## 持久状态与页面恢复

页面位置不是事实来源。恢复先读取最后一个**已提交边界**，再决定落在哪个只读页面：

| 已提交状态 | 重入页面 | 禁止恢复到 |
| --- | --- | --- |
| 第二幕尚未披露 | A 事实回看 | Bx 确认后的回应 |
| 第二幕披露已提交 | C 回应或已完成第二幕 | B 重新选择公开范围 |
| 第三幕说法尚未提交 | D 已知内容回看 | F 路线选择 |
| 第三幕说法已提交、路线未选 | Er 说法结果或 F 路线选择 | E 改写成另一处理 |
| `RouteOutcome=Stay` | G 或直接回地图 | F、Fz、Fzc |
| `RouteOutcome=Switch` 且替换完成 | G 或直接回地图 | Fs、再次替换 |
| Switch 标记与主说替换不一致 | 安全修复/阻塞页，禁止继续发奖 | 把半完成状态描述为成功 |

只读页面是否需要单独保存 `LastViewedPage` 属实现选择；即使不保存，也必须按上表回到不扩大权限的页面。玩家在确认页退出不会提交；玩家在确认回调完成后退出，重入必须看见提交后的状态。

## 重复确认与原子边界

### 第二幕披露

前置条件是 `DiogenesDisclosure=Unresolved`。提交后立即变为一个终态：`FactsAndReason`、`FactsOnly` 或 `Silent`。相同或不同按钮再次回调都被拒绝，不追加第二份历史。

### 第三幕说法

前置条件是 `StatementResolution=Unresolved` 且第二幕终态存在。提交时追加一条处理历史并更新当前说法；旧事实与旧公开说法不删除。重复回调不得追加两条修订。

### Stay

先写入 `RouteOutcome=Stay` 与“后续哲学切换关闭”，不替换主说。重复确认只返回已经完成，不再次保存或重开事件。

### Switch

它包含“验证当前主说可替换、执行替换、保存公开历史、写 `RouteOutcome=Switch`”四件事。纸面只规定它们必须表现为一个可验证事务：全部完成才进 G；任一步失败都不能展示成功页或丢掉原主说。具体先后与补偿由以后 API 审查决定，不能照搬东哲替换流程而跳过西哲状态一致性。

## D143判决与继续条件

A—F 页面已有统一的安全焦点、显式返回、确认边界和退出重入规则；第二幕三种披露、第三幕四类说法处理、Stay/Switch、重复确认和跨事件状态均能在纸面上保持知识不倒退。取消键无法拦截时采用“无动作”降级，不把取消映射成任何哲学选择。

D143结束时仍有三项技术事实未明：默认焦点/取消、同一事件换图、连续事件串接。D144已完成只读判决，见下节。两前史存档与芝诺主说本身仍未设计完成，交互线框不等于完整可玩路线。

## D144 原生事件 API 判决

审查对象是2026年9月20日本机安装的`sts2.dll`及仓库现有事件代码。临时反射与IL探针留在未跟踪的`tmp/D144ApiProbe`，不进入发布物，也没有启动游戏。

| 问题 | 已证事实 | 设计判决 |
| --- | --- | --- |
| 默认焦点 | `NEventLayout.DefaultFocusedControl`直接返回当前选项的第一项；`NEventRoom.SetOptions`每次重建按钮后调用`TryGrabFocus` | 确认页把“返回”放第一项即可获得安全初始焦点；页面刷新和返回都重新按选项顺序落焦 |
| 取消键 | 事件房间没有声明取消回调；按钮输入只处理`select`，程序集中的事件类型也没有可复用的取消方法 | 取消键保持无动作，导航全部走显式“返回”；不能把取消映射成沉默、Stay或Switch |
| 页内人物图 | `NEventRoom.SetPortrait(Texture2D)`是公开方法，调用布局的`SetPortrait`立即更新纹理；没有人物槽的布局会抛错 | 两个计划出现时点只用两个事件实例；第三幕Fz页内切芝诺图，返回F切回第欧根尼图。正式实现只能使用带人物槽的标准布局 |
| 连续事件 | `RunManager.EnterRoomWithoutExitingCurrentRoom`是公开方法，会把新房间压入当前房间栈；现有Mod已在涅奥后和第二幕地图后使用 | 原生有嵌套入口，但普通`Proceed`只开地图，不会自动串接下一事件。当前方案已经不需要第三事件，因此不把嵌套恢复风险带入制作 |
| 页面恢复 | `EventRoom.ToSerializable`只写事件ID和`IsPreFinished`；`SetEventState`只更新正文/选项并触发状态变化，普通事件状态变化不会自动保存 | A—G页都不是事实来源。读档只从最后一个已提交的自有局内状态重建合法页面和人物图 |
| 确认防重 | 非Proceed选项在执行选择前会禁用当前按钮，但这只是界面层的一次性保护 | 披露、说法、Stay和Switch仍要各自检查未决状态；重复回调只能返回既有结果，不能再次写历史或替换主说 |
| 保存边界 | 当前项目的`SaveRunAfterResolution`只在`RunManager.ShouldSave`时显式调用`SaveRun`；原生普通事件不会替这些页面提交保存 | 每个不可逆提交必须显式保存。保存成功前不显示完成页；保存失败保留可重试状态，不把内存变化描述成已落盘 |

Switch不能伪装成单次原子操作。下一设计阶段必须先写出`未决 → 切换准备 → 已提交`的局内状态契约：准备态先保存原主说和目标，实际替换后核验，再写已提交并再次保存；读档若遇到准备态，根据真实主说完成或回退，不重复授予。该契约和两条前史的生产字段通过纸面迁移表后，才评估最小实现。

D144因此通过的是**两事件、页内换图、显式返回、自有状态恢复**这套制作骨架，不是完整路线，也不是游戏内验收。下一步写回85当前人物入口中的持久状态契约和失败恢复顺序，不新增第94份想法页，不先制作人物图或接入生产事件。

## D145 持久状态与切换恢复契约

### 玩家需要理解的内容

系统只长期记住六件事：发生过哪一件前史、当时的事实、玩家当时选择的预写理由、第欧根尼后来知道多少、玩家第三幕是否改变说法、最终停留还是转向。它不保存“诚实分”“勇敢分”或隐藏好感，也不从沉默推断动机。

| 记录组 | 必须保存 | 不保存或不推断 |
| --- | --- | --- |
| 前史来源 | `SocratesVirtue`、`PlatoUnseenExchange`或`NoMaterial`三选一；一旦选定不可换源 | 不把人物名当品德标签 |
| 事实快照 | 苏格拉底的机会/行动/目的/标准/自评，或柏拉图的物品ID/价格/实付/是否取得/交易动作 | 不保存临时界面文案；不让后来的结果改写旧事实 |
| 私有理由 | 只能是上游已提交的预写理由ID，可为空 | 不保存自由文本，不让NPC读取未公开理由 |
| 第二幕披露 | `FactsAndReason`、`FactsOnly`、`Silent`或`NoMaterial`终态 | 不保存公开次数，不允许终态退回未决 |
| 第三幕说法 | 一次处理动作和处理前后理由ID；历史最多保留第二幕、第三幕各一条 | 不删除旧公开事实，不用新说法覆盖旧说法历史 |
| 路线结果 | Stay，或Switch的准备/提交状态；Switch准备态另存原主说与目标 | 不把Stay/Switch当思想正确性评分 |

前史快照只从已经通过各自生产保存的上游记录复制一次。苏格拉底或柏拉图只有纸面材料、字段缺失或校验失败时，来源必须是`NoMaterial`；第欧根尼事件不能根据当前生命、金币、遗物或玩家现状反推一段“应该发生过”的历史。

### 状态字段

建议未来把一份`DiogenesPublicAccountState`放入既有`PhilosophyRunState`，而不是塞进事件页面或人物图节点。纸面字段如下，代码名仍须在正式实现前按命名规则确认：

| 字段 | 合法值/结构 | 约束 |
| --- | --- | --- |
| `Version` | 正整数 | 旧版本只能显式迁移或安全拒绝 |
| `SourceKind` | `Unresolved / SocratesVirtue / PlatoUnseenExchange / NoMaterial` | 首次捕获后不可更换 |
| `SourceSnapshot` | 与来源匹配的判别联合 | 数值非负、ID来自白名单、不得跨来源混填 |
| `PrivateReasonId` | 预写理由ID或空 | 仅来源页和玩家自己可见 |
| `Disclosure` | `Unresolved / FactsAndReason / FactsOnly / Silent / NoMaterial` | 第二幕只有一次终态提交 |
| `StatementResolution` | `Unresolved / Kept / Added / Revised / Withdrawn / ContinuedSilence / NoMaterialKept` | 必须与Disclosure和理由前史相容 |
| `StatementBefore/After` | 预写理由ID或空 | 撤回只清当前理由，历史中的Before保留 |
| `RouteChoice` | `Unresolved / Stay / Switch` | 说法提交前不能选择路线 |
| `SwitchPhase` | `None / Prepared / Committed` | 非Switch时必须为None |
| `PreviousDoctrine` | 思想家ID和主说ID快照 | 只在Prepared/Committed存在 |
| `TargetDoctrine` | 芝诺思想家ID和主说ID | 正式芝诺命名未完成前不得伪造公开ModelId |

接收者知识由`Disclosure + StatementResolution + StatementBefore/After`推导，不另存一份可互相矛盾的“第欧根尼知道什么”。当前页面和当前人物图也不保存；它们始终由上述已提交状态重建。

### 四个提交事务

1. **披露：** 仅当`Disclosure=Unresolved`时接受一次选择。先保留内存旧值，写终态并显式保存；保存失败则恢复旧值，留在确认页，不显示回应页。
2. **第三幕说法：** 仅当披露已终结且`StatementResolution=Unresolved`时接受一次。写处理前后理由和动作并保存；失败恢复未决，不能追加第二条历史。
3. **Stay：** 仅当说法已提交、路线未决时写`RouteChoice=Stay`并保存。保存成功才进入完成页；主说始终不变。
4. **Switch：** 先验证当前主说仍等于即将保存的`PreviousDoctrine`，再写`RouteChoice=Switch + SwitchPhase=Prepared + PreviousDoctrine + TargetDoctrine`并保存。第一次保存成功后才执行替换；核验唯一主说已变为目标，再写`Committed`并第二次保存。任何一步都不能提前显示完成页。

Switch使用两次保存，不宣称跨遗物、路线状态和磁盘存在真正数据库事务。准备态的目的就是让中断可诊断、可恢复。

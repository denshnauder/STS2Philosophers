# 柏拉图商店制作可行性

## D126判决与范围

无名环保留核心设计候选，尚未批准生产。既有商店、药水图标与取得反馈可以复用，但附加交易选择不是原生现成能力；不以“没有新场景”掩盖界面和事务成本。不新增商人、背景、隐身动画或战斗目标，不生成美术。

来源是本机local.props游戏目录的sts2.dll只读反编译，SHA256 0861BFA1DF347538D932F22D580E75420F08082792EB914E53B4882764ACDBE9。七个有界类型：MerchantEntry、MerchantPotionEntry、MerchantInventory、MerchantRoom、PotionCmd、NMerchantPotion、NMerchantSlot。输出bin/design/native/merchant为忽略的开发材料，不复制上游源码到提交。没有执行采购、保存、实例化游戏或开启界面。

## 已核实与必须调整的假设

| 事项 | 源码事实 | 设计与制作判断 |
| --- | --- | --- |
| 价格 | MerchantEntry.Cost在商店调用ModifyMerchantPrice；药水基础价还受生成随机影响 | 读取实际货位当前报价，不用纸面100作真实价；确认前重新验证，确认后快照给同一笔补价 |
| 库存 | MerchantPotionEntry.Model是可变药水，IsStocked检查非空 | 同ModelId不保证同一货位或同一物品实例；一次选择要绑定本商店、货位和当前实例 |
| 取得 | PotionCmd.TryToProcure先检查ShouldProcurePotion，再AddPotionInternal；失败区分禁止与空间 | 空槽不是充分条件，不能忽视禁止取得；失败不消耗本幕机会、不删库存、不扣款 |
| 正常买 | OnTryPurchase先取得、再扣金币，其后购买历史与同步；Wrapper成功后可清货或补货、触发AfterItemPurchased | 原生异步步骤不是整个自定义事务原子性证明；不能复制纸面整体JSON还原到真实游戏 |
| 免费包装 | ignoreCost跳过扣金币，但仍BoughtPotions记录和SyncLocalGoldLost(Cost)，Wrapper仍AfterItemPurchased(0) | 不能直接称它“无人归责的未购买取用”，必须定义历史与回调一致性；不采用临时改价格0/取完再退钱掩盖 |
| 补货 | ShouldRefillMerchantEntry决定清空还是Restock | 原实例被取得可以导致新库存出现；不得强清补货后的新物品，实验机会仍消耗且新货只普通交易 |
| 操作 | NMerchantSlot鼠标与手柄选中直接调用交易；NMerchantPotion负责价格、购买成功/失败展示订阅 | 两种输入必须同一选择入口；阻止重复点击和普通交易并发，不能只改鼠标事件 |
| 房间 | MerchantRoom入场创建库存；恢复房间堆栈抛异常，Resume未实现 | 不以跳入事件房间再返回商店作为默认载体；源码不等于完整读档行为，库存保存/重建仍未核实 |

ShouldProcurePotion失败、满槽和免费合法赠品是程序条件，不命名为克己或不正义。库存历史可由本地程序记录，不自动升级为卖方认知或公共声誉；本设计不改原生历史来伪造匿名，所需“谁知道什么”边界见83。

## 正式呈现的可承担目标与未完工作

正式节点保持既有第二/三幕Shop，每幕至多一次。候选入口是在原生药水货位选中时出现就地交易选择面板，保留原商店对象，不切换房间。面板显示同一药水原生预览、当前价格、购买/匿名取用/取消实验及不足或禁止原因；取用成功后就地一次补价或结束。复用原生字体、按钮样式与药水素材是目标，具体可复用的面板/布局和控制器焦点尚未核实，不声称已经零成本可接入。至多一枚静态环图标，不制作额外过场。

报价变化时回到确认，失败后留本货位选择；获得物品后不能因回调异常回滚其他遗物/历史/金币，恢复要识别已发生步骤。本幕机会属于局内记录，不能仅存在环实例；需验证退出、换主说、重入、保存/加载及旧存档无记录时行为。不能用Godot对象SaveGodotObjectData冒称游戏存档协议已通过。

## 下一动作

先完成就地面板和交易语义规范：输入/焦点/取消、报价变化、空间与禁止、自动采购、补货、购买回调与公开历史、部分完成恢复；再决定是否批准最小原生诊断或改选载体。这是制作与哲学边界的设计任务，不先C#或生成图标。库存保存与真实界面需人工样本时独立登记，未自动启动游戏。守灯继续条件不解除，东哲/图边/公开ID不改。


## D127就地界面与交易语义规范（设计候选）

### 界面与输入成本

NModalContainer可容纳实现IScreenContext的节点并遮挡下层输入；已有模态时Add只警告返回。NGenericPopup公开接口只有是/否两种结果，DefaultFocusedControl为空；不能把它说成现成三选一商店面板。以上仅本机同哈希程序集读源，未运行Godot对象。拟制作一块小型三按钮面板，复用字体、按钮和药水预览，新增布局/输入逻辑，不新增背景或过场。需承担控制器默认焦点、返回键、弹窗冲突、关闭后焦点回到原货位及窄屏文本测试；这些是开发工作，不以零新美术作零成本。

保持同一货位一屏同时显示“购买（当前价）”“取用”“结束实验”。先看到具体物品、槽位和价格再作动作，默认焦点为结束实验，打开面板不自动确认。正常购买金币不足时灰显并简短说明；禁止/满槽的取得条件两种路径一致。未发生事务时返回键关闭选择，不消耗机会；明确结束实验才放弃本幕实验。私人回应仍可空，正式初版不强迫自由输入或加入教师读心。

面板已有模态时不抢占、不创建无人管理的等待任务；本次仍可稍后选择。关闭和成功均由持有者结束自己创建的模态，不全局清除其他窗口。以鼠标和手柄同一入口作为目标，不能把只拦鼠标的版本发布。遮挡下层手动输入不等于暂停异步或自动采购。

### 交易语义与原生副作用

| 动作 | 资源与记录目标 | 不能采用的捷径 |
| --- | --- | --- |
| 购买 | 延续正常购买与购买回调语义，记录实际支出；本幕实验成功结束 | 不为制造哲学差异改正常购买收益 |
| 取用 | 正常药水取得规则和取得回调；价款未付。独立事实记录明确来源为本商店取用，不伪装普通付费购买 | 不直接ignoreCost、不先付后退款、不临时改所有商店价格、不隐去程序历史当匿名证明 |
| 补价 | 已取得物不重复；向本笔原商店支付确认价一次，记录实际支出与先取用后付的顺序 | 不发第二次取得/购买奖励，不让下一商店收旧款，不抹去未付历史 |
| 结束/失败 | 结束实验不改资源；取得失败不扣款/删库存/消耗机会 | 不把槽位或API禁止叫品德失败 |

“取用不触发购买奖励”属于本设计明确语义，因为未购买；取得奖励照常发生，差异可见，不能声称两动作在所有遗物下战斗收益完全相同。匿名假设仅无人归责，程序日志仍诚实。补价是既得物的后续支付，不倒推原取用为普通购买；金币支付相关规则须核实真实原生类型及钩子，不能提前指定未知接口。正常采购和匿名取用遇到原生补货都应保留新货位，实验机会不刷新；匿名路径如何尊重购买限定补货/遗物规则须逐个语义核实，未批准伪触发所有购买钩子或一概删除效果。

### 失效、恢复与本幕机会

首次具备正价合法药水及取得条件的商店提供本幕实验；没有实际机会不记录拒绝。第一次合格商店结束实验或成功取得后本幕用尽；失败可以在同一商店修正。机会不放在环物实例上。出商店前尚未作取得时，只有明确结束实验才记主动放弃；关闭或外部失效不认证拒绝。后续商店是否仍给机会须由本幕合格商店绑定记录控制，不靠当前环重建资格。

货位、实例、商店、价格或资格变化后必须回到当前报价确认，不能继续对旧对象扣钱。自动采购仍走普通语义；若它先拿走所选实例，自定义事务失效，不拿补货新实例替代旧选择。免费货物回普通商店，不贴未付标签。异步处理中关闭/连点/换主说须停止新操作，不凭新环刷新。

恢复至少区分选择未提交、药水已取得但其他步骤未完、库存已更新、实际款已付及实验已终结。阶段记录必须与真实持有/库存/支付核对；发现不一致时保留证据，禁再次给物或自动重复扣款。不能承诺靠一个JSON或补写“已完成”即可恢复；实际保存边界/原生对象身份还未知。未经证明不得接入真实事务，更不能回滚其他遗物取得钩子或用户存档。

### 设计复查与继续条件

反例已逐项走查：不足金币仍可取用但补价不可用；空槽且被禁止取得仍失败；补货新物不被清掉；自动采购先拿走旧实例不暗换新货；费用变化重确认；免费商品不是欠付；已有模态不占用；返回关闭不是拒绝；取得回调后的异常不假称完全回滚；换主说不刷新；本地购买历史不等于公开声誉。这是纸面语义审查，没有自动测试或真实界面验收。

正式生产继续条件仍未满足。下一只读核实游戏存档/商店恢复边界与既有局内持久记录，判断能否保持一次真实取得和一次付款；避免先实现高风险机制。若必须依赖未能证明的中途恢复或额外场景，则拒绝该生产接法，保留思想实验并继续独立后继研究。
